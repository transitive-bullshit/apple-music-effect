# Project: apple-music-effect

A real-time, physically based recreation of the liquid logo animation from Apple Music's "Made by Sound" identity (Oct 2026): a WebGL2 rendering of a lens of oil with a player (custom logos, MP4 export), an explainer, and a headless renderer. See `contributing.md` for setup and commands.

## Conventions

- use `pnpm`
- use modern TypeScript (ESM only, no CommonJS)
- no semicolons; oxfmt formats (`pnpm fix:format`) and oxlint lints (`pnpm fix:lint`)
- `pnpm test` runs format, lint, types, and unit tests; keep it green
- use `ky` as a wrapper around `fetch` for HTTP requests
- use `zod` to validate external data
- for local development, use `pnpm dev` and the Portless URL it prints (apps only)
- use `uv` for the Python analysis (`analysis/`)

## Mental model

The film (`src/scene.ts`) is two shots, icon then wordmark, each a logo under one dome of oil → the dome (`src/dome.ts`) is four smooth curves (radius, height, morph, settle) between two profiles, fitted to Apple's film by `analysis/capture.py` into `data/dome/` → the engine (`src/engine.ts`) renders each pixel by spectral ray tracing through that closed-form surface (`src/shaders.ts`); there is no simulation → one page in two modes: the player (`index.html`) and render mode (`?mode=render`, driven by `scripts/render.ts`). `scripts/compare.ts` sets renders beside the reference film; `docs/effect-analysis.md` records what the film shows, the physics, and how each value was matched.

## Rules

- Frames are pure functions of time: no `Math.random()` or wall-clock time in the engine; seed anything random (by subframe, not frame, so a still picture stays still). The player, stills, renders and exports must agree.
- Motion must be smooth and simple: a few curves per shot with a few keys each, every animated value continuous in value and slope (C1). Interpolate keys, never cross-fade between shapes, never step a simulation or fit values per frame. `test/smooth.test.ts` enforces it; check renders' frame-to-frame change against the film's for spikes too.
- Measure before tuning: the film times are reel times (YouTube = reel + 69.334 s); placements are in world units (1 unit = 540 px at 1080p). Check changes with `pnpm compare`, by eye, and `analysis/scorecard.py` (the look as smoothed curves against the film's, per shot): keep a change only if both improve. `pnpm score` (RMS error) prefers soft, dark frames, so it only brackets.
- The sting audio is the master: never edit or re-time it.
- `data/timeline.json` is generated by `analysis/timeline.py`; its shape is a contract with `src/timeline.ts`.
- `data/dome/*.json` is generated by `analysis/capture.py`, whose dome model (`interpolate`, `dome_at`, `lens_z`, `refracted`) mirrors `src/driver.ts`, `src/dome.ts`, and `lensZ` and the optics in `src/shaders.ts`: change them together, and refit (`--fit`) rather than editing the files.

## Not in git

- `reference/` (Apple's film, reel and logos, including our traces) and `media/` (the sting): copyrighted and trademarked, never committed. Without them everything falls back to the demo brand in `public/demo/` and plays silent. The deliberate exceptions: the readme's comparison stills (`docs/film-before-now.webp`) and the site's share image (`public/og.png`, our render of Apple's wordmark).
- `frames/`, `renders/`, `dist/`, `analysis/out/` (the capture's registrations): regenerable output.
- `readme.md` is marketing; technical docs go in `contributing.md`.

## Checks

`pnpm test` and `uv run pytest -q`; CI also runs `pnpm build` and `py_compile`, offline. `uv sync` prunes `.venv` to the groups you name, so run the analysis with `uv run --group analysis`.
